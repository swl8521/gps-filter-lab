GPS Filter Lab은 원본 및 필터링 GPS 좌표를 비교하고,
이상 속도를 탐지하며, GPS 필터링 결과를 검증하기 위한
브라우저 기반 데이터 분석 도구입니다.

위치 기반 러닝 애플리케이션인
[PaceLeague](https://paceleague.co.kr)의 개발 과정에서
발생한 GPS 추적 문제를 해결하기 위해 시작한 프로젝트입니다.

## 개발 배경

GPS 추적 데이터는 위치 측정 오차, 신호 간섭,
노이즈 및 불규칙한 위치 업데이트 등의 영향을 받을 수 있습니다.

지도에서 GPS 경로를 육안으로 비교하는 것만으로는
필터링이 데이터 품질을 개선했는지 판단하기 어렵습니다.

GPS Filter Lab은 GPS 데이터를 정량적으로 분석하고,
필터링 과정에서 발생할 수 있는 부작용을 식별하기 위해
개발되었습니다.

## 주요 기능

### 1. CSV 가져오기 및 유효성 검증

- CSV 파일을 통한 GPS 추적 데이터 가져오기
- Papa Parse를 활용한 CSV 데이터 파싱
- 필수 필드 및 좌표 범위 검증
- 숫자, 시퀀스 및 타임스탬프 유효성 검증
- 오류가 발생한 CSV 행 번호 및 오류 메시지 표시
- 파일 가져오기 실패 시 기존 데이터 유지

### 2. GPS 거리 분석

- Haversine 공식을 활용한 좌표 간 거리 계산
- 원본 및 필터링 GPS의 총 이동 거리 비교
- 필터링 전후 이동 거리 변화율 계산
- 평균 및 최대 GPS 보정 거리 계산

### 3. GPS 속도 분석

- 좌표와 타임스탬프를 활용한 구간별 이동 속도 계산
- 평균 및 최대 이동 속도 계산
- 원본 및 필터링 GPS 속도 통계 비교
- 사용자 설정 임계값을 기반으로 이상 속도 탐지

### 4. 이상 속도 비교 분석

이상 속도 데이터를 다음 세 가지 상태로 분류합니다.

| 상태 | 설명 |
| --- | --- |
| Resolved (해결) | 원본에서 탐지되었으나 필터링 후 해소된 이상 속도 |
| Remaining (잔존) | 원본과 필터링 데이터 모두에서 탐지된 이상 속도 |
| Introduced (신규 발생) | 필터링 데이터에서만 새롭게 탐지된 이상 속도 |

이러한 분류를 통해 전체 통계만으로는 확인하기 어려운
필터링의 잠재적인 부작용을 식별할 수 있습니다.

### 5. 인터랙티브 지도 시각화

- 원본 및 필터링 GPS 이동 경로 표시
- 원본 GPS 경로에 맞춘 지도 영역 자동 조정
- 이상 속도 상태별 색상 마커 표시
- 마커 팝업을 통한 상세 속도 정보 제공
- 테이블 항목 선택 시 해당 GPS 지점으로 지도 이동
- 동일한 항목의 반복 선택 지원
- 지도 범례 제공

## 실제 데이터 분석 사례

실제 러닝 세션에서 수집된 670개의 GPS 좌표를
분석한 결과입니다.

### 이동 거리 비교

| 분석 항목 | 결과 |
| --- | ---: |
| 전체 GPS 좌표 수 | 670개 |
| 원본 이동 거리 | 8,381.55m |
| 필터링 이동 거리 | 8,406.45m |
| 이동 거리 변화율 | +0.30% |

### 이상 속도 비교

이상 속도 탐지 기준: 15km/h

| 분석 항목 | 개수 |
| --- | ---: |
| 원본 이상 속도 | 5개 |
| 필터링 이상 속도 | 4개 |
| 해결된 이상 속도 | 3개 |
| 남아 있는 이상 속도 | 2개 |
| 새롭게 발생한 이상 속도 | 2개 |

필터링 이후 전체 이상 속도 탐지 건수는
5개에서 4개로 감소했습니다.

그러나 개별 구간을 분석한 결과,
기존 이상 속도 3개가 해결되는 동시에
새로운 이상 속도 2개가 발생한 것을 확인했습니다.

이는 GPS 필터링 결과를 평가할 때 전체 통계뿐만 아니라
개별 GPS 구간에 대한 분석도 중요하다는 것을 보여줍니다.

단, 설정된 속도 임계값을 초과했다고 해서
반드시 GPS 측정 오류를 의미하는 것은 아닙니다.
추가적인 검증이 필요한 구간을 식별하는 지표로 활용합니다.

## 주요 기술적 구현

### 동일 구간 기반 이동 거리 비교

원본 GPS 좌표가 누락된 경우 서로 다른 구간을 비교하면
이동 거리 분석 결과에 편향이 발생할 수 있습니다.

이를 방지하기 위해 원본 좌표가 유효한 동일 구간을
기준으로 원본 및 필터링 이동 거리를 계산합니다.

### GPS 좌표 조회 최적화

GPS 좌표의 시퀀스 번호를 키로 사용하는
Map 자료구조를 구성했습니다.

지도 마커에 해당하는 GPS 좌표를 조회할 때
배열을 반복적으로 순회하는 대신 Map을 활용하여
조회 효율을 개선했습니다.

또한 React의 useMemo를 활용하여
관련 데이터가 변경되지 않은 경우
불필요한 재계산을 방지합니다.

### 상태 일관성 관리

- CSV 파싱 성공 이후에만 파일 관련 상태 업데이트
- 현재 속도 임계값을 기준으로 선택 항목의 유효성 검증
- 동일 항목 반복 선택 시 새로운 지도 이동 요청 처리
- 의존성 변경 시 기존 지도 이벤트 리스너 정리

### 예외 처리

CSV 데이터 검증 과정에서 오류가 발생하면
해당 행 번호를 포함한 오류 메시지를 제공합니다.

Error.cause를 활용하여 새로운 예외를 생성할 때도
원본 예외 정보를 보존하도록 구현했습니다.

## CSV 데이터 형식

GPS Filter Lab은 원본 및 필터링 GPS 좌표를
포함하는 CSV 파일을 지원합니다.

### CSV 예시

```csv
run_id,sequence,recorded_at,raw_latitude,raw_longitude,filtered_latitude,filtered_longitude,accuracy,altitude
run-001,0,1700000000000,37.500000,127.000000,37.500000,127.000000,5.0,30.0
run-001,1,1700000003000,37.500100,127.000100,37.500095,127.000098,6.0,30.5
```

### CSV 필드 설명

| 필드 | 설명 |
| --- | --- |
| `run_id` | GPS 추적 세션 식별자 |
| `sequence` | GPS 좌표의 순차적 인덱스 |
| `recorded_at` | Unix 타임스탬프 (밀리초) |
| `raw_latitude` | 원본 위도 |
| `raw_longitude` | 원본 경도 |
| `filtered_latitude` | 필터링 이후 위도 |
| `filtered_longitude` | 필터링 이후 경도 |
| `accuracy` | GPS 수평 위치 정확도 (m) |
| `altitude` | 고도 (m) |

원본 GPS 좌표와 고도는 누락된 값을 허용합니다.

현재 분석 기능은 하나의 기록 세션을 기준으로 하며,
GPS 좌표가 기록 순서대로 정렬되어 있고
각 시퀀스 번호가 고유하다는 것을 전제로 합니다.

## 현재 한계점

- 현재는 GPS 필터링 알고리즘을 직접 실행하는 것이 아니라
  기존 필터링 결과를 분석하는 기능을 제공합니다.
- 속도 기반 이상치 탐지는 휴리스틱 방식이며,
  GPS 측정 오류 여부를 확정할 수 없습니다.
- 일부 데이터셋에는 원본 추적 애플리케이션에서
  수용된 GPS 샘플만 포함되어 있습니다.
- 수용된 GPS 기록만으로는 기존에 제외된
  GPS 샘플을 복원할 수 없습니다.
- 적절한 기준 데이터(Ground Truth)가 없다면
  필터링의 실제 위치 정확도를 확정할 수 없습니다.

## 개인정보 보호

GPS 좌표에는 민감한 위치 정보가 포함될 수 있습니다.

- CSV 파싱 및 데이터 분석은 브라우저에서 수행됩니다.
- 현재 별도의 서버 업로드 기능을 구현하지 않았습니다.
- 지도 표시를 위해 외부 지도 타일 요청이 발생합니다.
- 실제 사용자의 위치 데이터를 공개 저장소에
  커밋하지 않는 것을 원칙으로 합니다.
- 공개 예시에는 가상 또는 익명화된 데이터를
  사용하는 것을 권장합니다.
